================================================================================
1. ERROR MASTER - FIELD CONSTRAINTS
================================================================================

FIELD               | TYPE              | REQUIRED | CONSTRAINTS
--------------------|-------------------|----------|--------------------------------------------
errorCode           | string            | YES      | 3-120 chars, pattern: ^[A-Za-z0-9_\.:-]{3,120}$
                    |                   |          | Must follow: ERR.<MODULE>.<COMPONENT>.<ACTION>
                    |                   |          | Example: ERR.AUTH.LOGIN.FAILED
                    |                   |          | IMMUTABLE after creation (cannot update)
errorType           | string            | YES      | Must exist in 'errorType' value-set
                    |                   |          | Allowed: BUSINESS, TECHNICAL, VALIDATION, SECURITY (case-insensitive)
errorSeverity       | string            | YES      | Must exist in 'errorSeverity' value-set
                    |                   |          | Allowed: LOW, MEDIUM, HIGH, CRITICAL (case-insensitive)
log                 | boolean           | NO       | Default: true
sourceType          | string            | YES      | Must exist in 'sourceType' value-set
                    |                   |          | Allowed: API, UI, SCREEN, FUNCTION, THIRDPARTY (case-insensitive)
sourceName          | string            | YES      | Max 200 chars
appCode             | string            | NO       | Optional application code identifier
notificationId      | string            | NO       | FK to notification_master._id (ObjectId hex)
moduleId            | string            | NO       | FK to modules._id (ObjectId hex)
businessArea        | string            | NO       | Max 120 chars
technicalArea       | string            | NO       | Max 120 chars
tool                | string            | NO       | Max 120 chars
partnerSystem       | string            | NO       | Max 120 chars
thirdParty          | string            | NO       | Max 120 chars
messages            | array             | YES      | At least 1 LocalizedMessage required
  messages[].language  | string         | YES      | ISO-639-1 code (e.g., "en", "hi", "te")
  messages[].template  | string         | YES      | Placeholders must be {lowerCamelCase}
devMessage          | string            | NO       | Max 2000 chars
helpLink            | string (URL)      | NO       | Must be valid HTTP/HTTPS URL
videoLink           | string (URL)      | NO       | Must be valid HTTP/HTTPS URL

UPDATE SCHEMA: All fields are OPTIONAL. errorCode CANNOT be updated.
Additional update fields: sourceType, sourceName, appCode, notificationId


================================================================================
2. ERROR LOG - FIELD CONSTRAINTS
================================================================================

FIELD               | TYPE              | REQUIRED | CONSTRAINTS
--------------------|-------------------|----------|--------------------------------------------
errorCode           | string            | YES      | Must reference an existing error_master errorCode
parametersJson      | object (dict)     | NO       | Default: {} - key/value pairs for placeholders
language            | string            | NO       | Default: "en", ISO-639-1 (2 lowercase letters)
actorUserId         | string            | NO       | ObjectId hex string (24 hex chars)
sourceType          | string            | YES      | Must exist in 'sourceType' value-set
                    |                   |          | Allowed: API, UI, SCREEN, FUNCTION, THIRDPARTY
sourceName          | string            | YES      | Max 200 chars
userAgent           | string            | NO       | Max 512 chars
environment         | string            | NO       | Must exist in 'environment' value-set
                    |                   |          | Allowed: DEVELOPMENT, STAGING, PRODUCTION, QA
parameters          | array             | NO       | List of {name, value} pairs (both min 1 char)


================================================================================
3. DASHBOARD REQUEST - FIELD CONSTRAINTS
================================================================================

FIELD               | TYPE              | REQUIRED | CONSTRAINTS
--------------------|-------------------|----------|--------------------------------------------
timeRange           | string (enum)     | NO       | Default: "all". Values: all, 1h, 24h, 7d, 30d
fromDate            | datetime (ISO)    | NO       | ISO 8601 format
toDate              | datetime (ISO)    | NO       | ISO 8601 format
sourceType          | string            | NO       | Filter by source type
errorSeverity       | string            | NO       | Filter by severity
errorCode           | string            | NO       | Filter by specific error code
moduleId            | string            | NO       | Filter by module ID
includeArchive      | boolean           | NO       | Default: false
page                | integer           | NO       | Default: 1, min: 1
limit               | integer           | NO       | Default: 5, min: 1, max: 200


================================================================================
4. VALUE-SET REFERENCE (seeded in value_sets_master)
================================================================================

errorType:     BUSINESS, TECHNICAL, VALIDATION, SECURITY
errorSeverity: LOW, MEDIUM, HIGH, CRITICAL
sourceType:    API, UI, SCREEN, FUNCTION, THIRDPARTY
environment:   DEVELOPMENT, STAGING, PRODUCTION, QA

NOTE: All value-set fields accept any case (e.g., "Business" -> "BUSINESS")

17. RECOMMENDED TESTING ORDER
================================================================================

Step 1: Create error masters (POST /error-master/create) - use Tests 1-8
Step 2: Verify with list (GET /error-master/list)
Step 3: Get by ID (GET /error-master/get/{id}) - use ID from Step 1
Step 4: Get by code (GET /error-master/get/by-code/ERR.AUTH.LOGIN.FAILED)
Step 5: Update (PATCH /error-master/update/{id}) - use Tests 1-6
Step 6: Create error logs (POST /error-logs/create) - use Tests 1-6
Step 7: List error logs (GET /error-logs/list)
Step 8: Export CSV (GET /error-logs/export)
Step 9: Dashboard (POST /error-logs/dashboard) - use Tests 1-9
Step 10: Delete error master (DELETE /error-master/delete/{id})
Step 11: Restore error master (PATCH /error-master/restore/{id})
Step 12: Bulk create (POST /error-master/bulk-create)

NOTE: Error logs reference error masters by errorCode, so create the
      error masters FIRST before creating error logs.
